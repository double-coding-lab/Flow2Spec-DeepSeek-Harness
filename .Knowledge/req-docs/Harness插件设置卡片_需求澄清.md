# Harness 插件设置卡片 需求澄清

## 背景与目标

DeepSeek Harness `0.1.0-rc.7` 允许第三方插件在 Web「设置 → 插件配置」中出现自己的卡片。Flow2Spec 原生插件已有 Cordis `Config`，但那些字段是实现逃逸口，不是用户要做的产品选择；把它们做成开关，关掉之后只会让插件更难用。

本需求要让插件在官方设置页以一等公民出现：**展示只读状态**，并提供 **「检查更新」** 动作。用户打开卡片是为了确认「装上了、版本对、能不能升级」，不是为了把能力拆掉。

## 范围

### 包含

- 在 Harness Web「设置 → 插件配置」展示 Flow2Spec 卡片。
- **只读状态**：插件版本、Flow2Spec Core 版本、当前宿主是否通过兼容检查、当前工作区是否已有项目基线。
- **检查更新**按钮：比对已安装插件与 npm 上的插件版本，并检查 Core 是否有更新（与现有 `/flow2spec update` 同一类检查）。
- 检查结果写回卡片：已是最新 / 发现新版本 / 检查失败。发现新版本时只提示建议操作（例如用 `dsh plugin` 升级插件），**不在卡片内执行安装或改依赖**。
- 无工作区时，项目基线显示为「未关联项目」，不报错、不假装已初始化。

### 不包含

- 不上任何会降低能力的配置开关（包括但不限于：`locale`、`autoInitialize`、`strictCompatibility`、Skill/命令/工具启用、路由注入、路由上限、hooks、知识库写入）。
- 不在卡片上编辑 `.Knowledge/`、`flow2spec.config.json` 或协作/`changeTracking`。
- 不在卡片上执行插件安装、Core 升级、知识库 build/apply、项目初始化。
- 不另做独立 Web 管理页；只使用 rc.7 官方插件配置卡片缝。
- 不改变 CLI、`/flow2spec` 命令、模型工具的既有行为（检查更新可复用现有 Core 检查能力，命令本身保持可独立使用）。
- `cordis.yml` 中的完整 `Config` 继续作为高级/排障逃逸口，不作为本卡片产品功能。

## 关键流程

### 打开卡片

1. 用户在 Harness Web 打开「设置 → 插件配置」，看到 Flow2Spec 卡片。
2. 卡片立即展示只读状态；检查更新结果区为空闲（尚未检查）或显示上一次本会话内的检查结果。
3. 若当前没有工作区 cwd，项目基线项为「未关联项目」。

### 检查更新

1. 用户点击「检查更新」。
2. 按钮进入进行中状态，避免连点。
3. 同时（或连续）检查：
   - 插件包 `@double-coding/flow2spec-deepseek-harness`：已装版本 vs npm 登记版本；
   - Flow2Spec Core：沿用现有更新检查能力。
4. 卡片展示汇总：
   - 均为最新：明确写「已是最新」；
   - 任一侧有新版本：写明哪一侧、当前版本、可更新到的版本，以及建议的升级方式（插件走 Harness `dsh plugin`；Core 随插件依赖，不引导用户单独改 Core 来绕过插件兼容矩阵）；
   - 失败：写明失败原因（网络、仓库不可达、超时等），保留已展示的只读状态，不清空。
5. 检查结束，按钮恢复可点。

## 边界与异常

- 卡片挂在 Harness **profile / 插件配置** 上，不是仓库内的第二份项目配置。
- 项目基线状态依赖当前工作区；没有工作区时降级为「未关联项目」，不触发初始化、不写文件。
- 「检查更新」只读远程版本信息，不写 `package.json`、不跑 `npm install`、不调用会改机器状态的升级命令。
- 兼容检查失败时，只读状态里如实显示未通过；仍允许点「检查更新」（用户可能正是来看该不该升级）。
- 检查进行中再次点击：忽略或保持进行中，不并行打出两次完整检查。
- 文案：卡片中文为主，英文按 Harness 界面语言提供对照（若宿主卡片机制要求 locale key）；不把插件 `Config.locale` 做成用户可选项。

## 关键概念定义

| 概念 | 定义 |
|---|---|
| 只读状态 | 卡片上不可编辑的健康信息，用于确认插件已加载且版本/兼容/项目基线可知。 |
| 检查更新 | 用户主动触发的版本比对。只报告，不安装。 |
| 项目基线 | 当前工作区是否已具备 Flow2Spec 增量初始化后的最小项目事实（如 `.Knowledge/` 与 `flow2spec.config.json`）。由插件既有项目运行时判断，不在本需求中重新定义初始化算法。 |
| 插件配置 `Config` | Cordis 入口上的实现配置。本需求不把它映射为卡片开关。 |

## 验收标准

- 安装并启用插件后，Web「设置 → 插件配置」出现 Flow2Spec 卡片。
- 卡片可见插件版本、Core 版本、宿主兼容结果、项目基线（或「未关联项目」）。
- 卡片上 **没有** 可把自动初始化、知识注入、命令、工具或写入能力关掉的控件。
- 点击「检查更新」后，能看到成功（最新或有新版本+建议操作）或失败原因；检查过程中不会安装任何包。
- 无工作区时卡片仍可打开，且不会因为缺少 cwd 而崩溃或误写项目文件。
- `/flow2spec update` 与模型工具行为不被本需求改坏。
